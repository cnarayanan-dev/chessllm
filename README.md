# ChessLLM

Play chess against a small local LLM in the browser. See `CONTEXT.md` for the domain language and `docs/adr/` for decisions.

- Run the app: build the page first (needs Node and pnpm): `pnpm install && pnpm build` in `frontend/`. Then `uv run chessllm` (or `uv run python -m chessllm`), and open http://127.0.0.1:8000. The opponent is qwen3.5:9b, so Ollama must be running with that model installed. The page is the React app in `frontend/`; its build goes to `chessllm/static/dist/`, which is git-ignored, and isn't rebuilt on its own: build again after changing `frontend/`
- See the leaderboard: the Analytics link in the top bar, or http://127.0.0.1:8000/analytics. It ranks every Player configuration by Rating, from the finished games in `games/`; the "All columns" switch adds the Rating's interval, the Move-quality estimate and the legal-move metrics
- Work on the React page: `scripts/dev.sh` runs the app and `pnpm dev` together (Ctrl-C stops both), then open the address Vite prints. It reloads as you edit and forwards `/api` and `/static` to the app
- Run the frontend tests: `pnpm test` in `frontend/`. Typecheck it: `pnpm typecheck`
- Run the Playwright journeys (a game to checkmate, an illegal LLM try, a forfeit, a promotion, a faceoff, the leaderboard): `pnpm e2e` in `frontend/`, after `pnpm build`. The first time, install the browser: `pnpm exec playwright install chromium`. They play the built page against the app with scripted LLM players (`tests/e2e/server.py`, started on a free port), and the leaderboard against synthetic game logs (`tests/e2e/leaderboard.py`), so Ollama isn't needed
- Edit the LLM's system prompt: `chessllm/game/prompts/system.txt`. It is a template: `$color` and `$opponent` are filled in with the colours the LLM and the human play, and the `$example_...` placeholders with a worked first move for that colour
- Every game is saved in `games/`: a JSON Lines log of every move and LLM attempt, and a PGN file when the game ends
- Play an Anchor match (an LLM against Komodo Dragon 1, unattended): `uv run anchor-match --model llama3:8b --skill 1 --color white --dragon PATH`; `--help` lists the LLM's settings, among them `--thinking-level LEVEL` for one of the Thinking levels the model offers (e.g. `xhigh` for qwen3.8:latest) and `--thinking-budget TOKENS` for a Thinking budget (64-6,144 tokens per attempt, with thinking on; ADR 0007), benchmark only. Dragon isn't bundled: download `dragon.zip` from komodochess.com and pass the executable with `--dragon` or set `CHESSLLM_DRAGON`. Its macOS build is x86_64 only and runs under Rosetta 2 on Apple silicon. Where Dragon can't be had, `--engine stockfish` plays Stockfish instead (from `--stockfish`, `CHESSLLM_STOCKFISH` or the PATH): a rough stand-in with guessed ratings, rated as its own Anchor, and the only Anchor that can play under Chaos rules (`--rules chaos`). First results: `docs/research/llama3-anchor-matches-2026-10-19.md`
- Rate a Player configuration with a batch of Anchor matches: `uv run anchor-batch --model llama3:8b --games 30 --dragon PATH` (the LLM's settings as for one Anchor match). Colours alternate, and Dragon's Skill is judged after each pair of games at it (one as White, one as Black): over 50% steps up a level, under 50% steps down, within Skill 1-7. It prints each game's result and a summary. Running it again for the same configuration goes on where its earlier games left the ladder; `--skill N` starts at Skill N instead. Each game is analysed as it ends, with Maia-2 and Stockfish (`--no-analysis` to skip); an engine that can't start is left out with a warning, and `uv run analyse-games` can catch up later. Ctrl-C stops it, leaving every finished game's log complete
- Play a batch of LLM faceoffs (two models against each other, unattended): `uv run faceoff-batch --models gemma3:12b llama3:8b --games 9`. Colours alternate, both sides share the LLM's settings (`--help` lists them; `--thinking-for MODEL` turns thinking on for one model only, `--thinking-for qwen3.8:latest=xhigh` at one of its Thinking levels, `--thinking-budget-for qwen3.8:latest=3072` gives it a Thinking budget), and each game is analysed as it ends (`--no-analysis` to skip). First results: `docs/research/gemma-vs-llama-faceoffs-2026-10-19.md`
- Analyse the finished games (each one's Move-quality estimate with Maia-2, and centipawn loss and accuracy with Stockfish, in an analysis file next to its log): `uv run analyse-games` analyses every finished game without one, `--all` every finished game
- Report on the game logs: `uv run games-report` prints each Player configuration's record (by Dragon Skill against Anchors), how games ended, recurring themes (illegal moves and their phase, streaks, forfeits, mates in one, openings, Stockfish and Move-quality numbers when analysed) and the games. Filter with `--mode`, `--model`, `--constraints`, `--rules`, `--since YYYY-MM-DD[THH:MM]` and `--include-unfinished`; `--json` for JSON
- Run the tests: `uv run pytest`. They are in `tests/`, in folders that mirror the package (`api/`, `game/`, `llm/`, `engines/`, `analytics/`, `cli/`, and `scripts/` for the scripts), with the live tests in `tests/live/` and the Playwright server in `tests/e2e/`. The live tests are left out: `uv run pytest -m ollama` (Ollama with llama3:8b, and qwen3.8:latest for the Thinking budget) and `uv run pytest -m dragon` (needs `CHESSLLM_DRAGON`)
- Typecheck: `uv run mypy`
- Regenerate the sample games (`docs/samples/`: scripted games' logs and API responses, to check a refactor with `git diff`): `uv run python -m scripts.sample_logs`
- Rebuild the merida piece sprite: `uv run python scripts/build_merida_sprite.py`

Pieces: Merida by Armando Hernandez Marroquin, GPLv2+.
