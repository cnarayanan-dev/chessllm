# The Thinking budget is in tokens, enforced by a forced answer, per attempt, with the time limit as a safety net

A thinking model's turns took anywhere from 35 s to over 300 s, and qwen3.8 forfeited a game it was well ahead in by thinking past the time limit. In the benchmark only, a thinking LLM side can now have a Thinking budget: the most tokens of thinking and answer it may produce in one attempt before it is made to answer.

- **In tokens, not seconds.** A token is the same on any machine and under any load; a second is not. A budget in tokens keeps games played on a faster or busier computer comparable, and makes the budget part of the Player configuration (ADR 0005: games with different budgets are different configurations, and no budget leaves the configuration and its id as before).
- **Enforced by a forced answer.** The Ollama player caps the call at the budget (`options.num_predict`). If it stops for length, it makes exactly one more call with the same model, the same `think` value (level included) and the same `format` (the answer schema, and under Enforced decoding the same legal-move enum), the turn's messages and an assistant message `{"thinking": ..., "content": " "}`, capped at 64 tokens. Cut while thinking, the thinking so far is handed back closed with "Considering the limited time, I have to give my move now, based on the thinking so far."; cut while answering, the thinking was complete and goes back unchanged. The content must be a single space: with an empty one the models think again and give no answer. This was verified for qwen3.5:9b, qwen3.8 and gemma4:26b on Ollama 0.40.0 (`docs/research/thinking-budget.md`, "Verified"), so one code path serves all three. The reply says the answer was forced, and each llm_attempt logs `forced: true` (left out otherwise, so attempts without a budget log as before).
- **Per attempt.** A Retry gets a fresh budget. A forced answer that is illegal is an ordinary illegal move with the usual Retry.
- **A cut-off forced answer is its own result, `cut_off`.** If the forced call also stops at its cap without a parseable answer, there is no move to judge. It is not an illegal move, so the legal-move metrics don't count it (illegal-move counts, the Legal-move streak and recovered turns are untouched). It takes an attempt and gets a Retry with a fresh budget and a message saying the reply was cut off; a turn of nothing but cut-offs ends in a Forfeit like one of illegal moves. Only a side with a budget can have one: without a budget a length stop is judged as before, so the app's games and the API's result kinds don't change.
- **The time limit stays as a safety net, derived from the budget.** A timeout is still a Forfeit. Each call's limit is `max(300, 60 + 1.5 × budget ÷ speed)` seconds, with a conservative generation speed per model in the model list (qwen3.5:9b 20, qwen3.8 18, gemma4:26b 36 tok/s, the low end of the spike's measurements). The 1.5 covers a slower GPU with 50% to spare, and the 60 s the prompt, the forced call's re-prefill (MLX's prefix cache isn't reliable) and a model swap between faceoff turns. For qwen3.8 at 3,072 tokens it gives 316 s.
- **Refused before any game, with the reason:** a budget with thinking off (it could do nothing), a budget below 64 tokens (the forced answer's cap: too small to hold an answer), and a budget above 6,144 tokens (the 8,192-token context Ollama loads these models with must also hold a late-game prompt of up to ~1,500 tokens and the forced answer).

## Considered Options

- **A budget in seconds, cancelling the call at the deadline**: simple, but it measures the machine rather than the model, and a game played next to another model on the GPU would get less thinking for the same setting.
- **`num_predict` alone, treating a cut as the move**: no second call, but a cut reply has no move, so every bound budget would eat a Retry as an invalid move.
- **Refuse a budget whose worst case doesn't fit the fixed 300 s limit**: keeps one limit, but it ties a sane budget to this machine's speed (qwen3.8 at 4,096 tokens would be refused) and puts seconds back into what a budget means.
- **Raw generation with the template written out** (`/api/generate` with `raw: true`), continuing the model's own turn: verified as working for gemma4:26b, and kept as the fallback should a later Ollama renderer drop the handed-back thinking. The chat route needs no model-specific code.
- **Ollama's own `think_budget` option** (PR #17566, not shipped): one call instead of two. Switch to it when it ships and is checked on MLX models.

## Consequences

- A forced answer's thinking tokens are the first call's (exact when it was cut while thinking; split by characters when cut while answering), its answer tokens the forced call's, its prompt tokens the first call's, and its stop reason the forced call's. The analysis script reports the share of forced answers among a budgeted configuration's attempts with an answer, and the cut-offs.
- The Thinking budget, like the Thinking level, can be set only through the batch commands (`--thinking-budget-for MODEL=TOKENS` for a faceoff, `--thinking-budget TOKENS` for an Anchor match or batch). The API refuses it, and its types and output don't change.
- The speeds in the model list are this machine's. On a slower machine a timeout says the machine was too slow, not that the model thought too long; the budget, and so the configuration, stays the same.
- A budget above 6,144 tokens would need a larger `num_ctx`, a new setting of the Player configuration.
